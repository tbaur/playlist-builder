# Spotify Integration (EXPERIMENTAL)

> ⚠️ **Experimental Feature**: Spotify support is experimental and may have issues. Please report bugs.

This document describes the Spotify music service integration in playlist-builder.

## Overview

The Spotify integration allows playlist-builder to:
- Resolve tracks discovered by Gemini on Spotify's catalog
- Create and manage playlists in your Spotify account
- Authenticate using OAuth 2.0 (Authorization Code flow)

## Status: Experimental

This feature is marked experimental because:
- Limited production testing
- No quality tier support (Spotify doesn't expose lossless via API)
- OAuth redirect requires local server on port 8888

## Prerequisites

### 1. Create Spotify Developer App

1. Go to [Spotify Developer Dashboard](https://developer.spotify.com/dashboard)
2. Click "Create App"
3. Fill in app details:
   - App name: `playlist-builder` (or your choice)
   - App description: Personal playlist management
   - Redirect URI: `http://localhost:8888/callback`
4. Save and note your **Client ID** and **Client Secret**

### 2. Store Credentials

```bash
# On macOS (recommended)
playlist-builder keychain set SPOTIFY_CLIENT_ID
playlist-builder keychain set SPOTIFY_CLIENT_SECRET

# Or set in config.json
{
  "SPOTIFY": {
    "CLIENT_ID": "your_client_id",
    "CLIENT_SECRET": "your_client_secret"
  }
}
```

## Architecture

### SpotifyProvider Class

Located in `spotify_engine.py`, the `SpotifyProvider` class handles all Spotify API interactions.

```python
class SpotifyProvider:
    def __init__(self, cfg: Dict, cfg_path: str, debug: bool = False)
    def authenticate(self) -> bool
    def publish(self, name: str, tracks: List[Dict], replace: bool, metrics: Any) -> None
```

### Key Methods

| Method | Description |
|--------|-------------|
| `authenticate()` | Handles OAuth 2.0 flow with token refresh |
| `_resolve_best_node()` | Searches Spotify for best matching track |
| `_clean()` | Normalizes text for fuzzy matching |
| `publish()` | Creates/updates playlist with resolved tracks |
| `_get_credentials()` | Retrieves client credentials from Keychain/config |

## Authentication

### OAuth 2.0 Flow

Spotify uses OAuth 2.0 Authorization Code flow:

1. Check for cached tokens in Keychain (macOS) or config.json
2. If tokens exist, check expiration and refresh if needed
3. If no valid tokens, open browser for user authorization
4. User grants permission, receives callback on localhost:8888
5. Exchange code for access + refresh tokens
6. Save tokens to Keychain for future use

### Required Scopes

```python
SPOTIFY_SCOPES = "playlist-modify-public playlist-modify-private playlist-read-private"
```

| Scope | Purpose |
|-------|---------|
| `playlist-modify-public` | Create/edit public playlists |
| `playlist-modify-private` | Create/edit private playlists |
| `playlist-read-private` | Read user's private playlists |

### Session Storage

**macOS (Recommended)**
```

Account: spotify:spotify_session
Data: JSON with access_token, refresh_token, expires_at, etc.
```

**Other Platforms**

## Track Resolution

### Matching Algorithm

1. **Search Query**: Builds query as `track:"{title}" artist:{artist}`
2. **Title Tokenization**: Cleans and tokenizes track names
3. **Artist Anchor**: Uses first word of artist name for validation
4. **Score Calculation**: Jaccard similarity on title tokens
5. **Best Match**: Returns highest scoring track above threshold

### Differences from Tidal

| Aspect | Tidal | Spotify |
|--------|-------|---------|
| Quality weighting | Yes (Hi-Res, Lossless) | No (not exposed via API) |
| Search syntax | `"{title}" {artist}` | `track:"{title}" artist:{artist}` |
| Track ID format | Numeric ID | Spotify URI (`spotify:track:...`) |
| Batch add limit | Unlimited | 100 tracks per request |

### Minimum Match Score

Tracks must score above `MIN_MATCH_SCORE` (0.40) to be considered valid matches.

## Playlist Management

### Creating Playlists

```python
client.user_playlist_create(
    user_id, 
    name, 
    public=False,  # Private by default
    description="AI Generated by playlist-builder"
)
```

### Replacing Existing Playlists

When `--replace` flag is used:
1. Find existing playlist by name
2. Get all tracks in playlist
3. Remove all tracks using `playlist_remove_all_occurrences_of_items`
4. Add new resolved tracks

### Adding Tracks

Spotify limits batch additions to 100 tracks:

```python
# Batched in groups of 100
for i in range(0, len(uris), 100):
    batch = uris[i:i+100]
    client.playlist_add_items(playlist_id, batch)
```

## Usage

### Basic Search and Publish

```bash
# Search for tracks (caches results)
playlist-builder search "Electronic chill vibes"

# Publish to Spotify (experimental)
playlist-builder publish spotify --name "Chill Vibes"

# Replace existing playlist
playlist-builder publish spotify --name "Chill Vibes" --replace
```

### Debug Mode

```bash
playlist-builder search "query" --debug
```

## Error Handling

### Common Errors

| Error | Cause | Solution |
|-------|-------|----------|
| `Spotify credentials not configured` | Missing CLIENT_ID/SECRET | Set via keychain command |
| `SpotifyException 401` | Token expired | Auto-refreshes, re-auth if fails |
| `SpotifyException 403` | Insufficient scopes | Re-authenticate with correct scopes |
| `Port 8888 in use` | Another app using port | Stop conflicting app or change redirect URI |

### Retry Logic

The `_resolve_best_node` method uses exponential backoff:
- Max retries: 3
- Base delay: 1 second
- Handles transient API failures

## Dependencies

- `spotipy>=2.23.0` - Spotify Web API client

## Security Considerations

1. **Client credentials** stored in macOS Keychain (encrypted)
2. **OAuth tokens** stored in Keychain, auto-refreshed
3. **Config file** permissions set to 600 (owner read/write only)
4. **Redirect URI** uses localhost only (no external callbacks)

## Limitations

1. **No quality tiers**: Spotify API doesn't expose audio quality info
2. **Private playlists only**: Created playlists default to private
3. **100 track batch limit**: Large playlists require multiple API calls
4. **Localhost redirect**: OAuth requires browser on same machine
